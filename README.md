## Repository Setup

After cloning, run the following command once to configure a local git filter that suppresses noise from `io-expander.prjx`:

```powershell
git config filter.prjx_clean.clean "grep -v -E '^(TIME|SIZE)=' | sed '/^LIST OpenedFileList/,/^ENDLIST/d'"
```

### Why this is needed

Libero SoC updates `io-expander.prjx` every time the project is opened or a build is run with changes that carry no functional information:

| Noise | Description |
|-------|-------------|
| `TIME=` lines | Internal file-tracking timestamps, updated on every open/build |
| `SIZE=` lines | Cached file sizes, updated on every open/build |
| `LIST OpenedFileList` block | Tracks which files are open in the Libero editor and the active view |

Without the filter, `git status` always shows `io-expander.prjx` as modified even when nothing meaningful has changed.

The filter is defined in `.gitattributes` (tracked) but the filter command itself must be registered in your local `.git/config` (not tracked) — hence the one-time setup step above.

## SmartDesign and Generated HDL

The top-level design (`component/work/Top/Top.vhd`) and sub-block HDL files are **auto-generated by Libero's SmartDesign** feature from their corresponding `.cxf` source files. The generated `.vhd` files are committed to this repository for readability and traceability, but the `.cxf` files are the authoritative source.

> **Important:** After modifying any SmartDesign component in Libero (`.cxf`), you must regenerate the HDL before committing:
>
> 1. In Libero, right-click the SmartDesign component → **Generate Component**
> 2. Verify the updated `.vhd` is written to `component/work/<component>/`
> 3. Commit both the `.cxf` and the regenerated `.vhd` together
>
> Committing a `.cxf` change without the corresponding `.vhd` regeneration will leave the two files out of sync.

## Custom HDL Modules

The following modules are hand-written (not generated by SmartDesign) and live in `hdl/`:

| Module | File | Documentation |
|---|---|---|
| I2C Slave Controller | `hdl/i2c_slave.vhd` | [`docs/i2c_slave.md`](docs/i2c_slave.md) |
| Register File | `hdl/register_file.vhd` | [`docs/register_file.md`](docs/register_file.md) |

`i2c_slave` implements a 10-state Moore FSM supporting 7-bit addressing, write/read transactions, repeated start, and auto-increment burst reads. SDA output is driven combinatorially from the FSM state. State transitions to ACK states occur on the 8th SCL **falling** edge to ensure SDA is never driven low while SCL is high (which the master would misinterpret as a START condition).

`register_file` provides 16 byte-wide registers accessible over the I2C register bus and a dedicated application interface. Register reads are **combinatorial** (asynchronous), eliminating pipeline latency between the slave controller and register storage.

## Simulation

Pre-synthesis simulation is provided using ModelSim and the Libero-precompiled IGLOO library.

```tcl
# From within ModelSim, source the run script:
do simulation/run.do
```

The script compiles `component/work/Top/Top.vhd` and the testbench in `stimulus/tb_i2c_system.vhd` into the `presynth` library, then simulates `testbench` for 1000 ns.

> The `vmap igloo` path in `simulation/run.do` is absolute and points to the local Libero SoC installation (`C:/Microsemi/Libero_SoC_v11.9/...`). Update this path if your installation differs.
